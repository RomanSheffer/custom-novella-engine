# 🐈 Конструктор визуальных новелл (CNEngine)

Это готовый автономный No-Code движок для создания собственных визуальных новелл и текстовых квестов. Продукт полностью ориентирован на обычных пользователей и **не требует навыков программирования** — игра собирается простым переименованием файлов по правилу номеров и запускается через один клик.

В то же время данный проект является чистым архитектурным Pet-проектом, написанным по строгим стандартам качества кода и рекомендациям SonarQube.

---

## 🕹️ ИНСТРУКЦИЯ ДЛЯ СОЗДАТЕЛЕЙ ИГР 

### ❗Для начала работы
* Скопируйте папку "custom_engine_output/CustomNovellaEngine" на рабочий стол
* добавьте в нее папку levels из корня проекта. Там уже есть демонстрационная новелла, написанная мной
* При создании своей новеллы можно удалить все в папке levels и положить туда свои файлы


### 📌 Главный принцип: Правило одного номера
Вся логика движка строится на сквозной нумерации файлов. Чтобы игра поняла, какие ресурсы относятся к конкретному экрану (слайду), **все файлы этого экрана должны называться одинаковым номером**.

Для создания **первого уровня** (стартового экрана) в папку игры нужно положить:
* `1.json` — Логика кнопок и переходов *(обязательный файл)*
* `1.txt` — Текст самого сюжета для этой сцены
* `1.jpg` — Фоновая картинка для этого экрана
* `1.wav` — Короткий звуковой эффект при открытии слайда (например, скрип двери)
* `1theme.wav` — Фоновая музыка, которая будет циклично играть на этом уровне

* ### ❗К одному уровню можно применить только один звук и одну муз. тему одновременно. Форматы файлов необходимо строго соблюдать 

### 📁 Структура папки `levels`
Создайте папку с именем `levels` прямо рядом с исполняемым файлом игры и соберите туда все файлы вашей истории:
```text
📁 levels/
├── 📄 1.json          # Логика кнопок для 1-го уровня
├── 📝 1.txt           # Текст для 1-го уровня
├── 🖼️ 1.jpg           # Фон для 1-го уровня
├── 🎵 1theme.wav      # Музыка для 1-го уровня
├── 🔊 1.wav           # Звук для 1-го уровня
├── 📄 2.json          # Переходы для 2-го уровня...
└── 📝 2.txt           # Текст для 2-го уровня...
```

### 📝 Структура файла логики (JSON)
Файл конфигурации (`.json`) имеет кристально простую и понятную структуру. В нём указывается ID текущего уровня и карта кнопок: текст, который увидит игрок, и номер слайда, на который эта кнопка его отправит.

**Пример правильного файла `1.json`:**
```json
{
  "levelId": 1,
  "buttonsMap": {
    "Пойти искать еду": 2,
    "Осмотреться в комнате": 21
  }
}
```
* ###  ❗Количество кнопок может быть любым. просто добавьте запрятую и ниже подобную структуру описания кнопки

### 🏁 Как сделать финал игры?
Когда история подходит к концу и вам нужно завершить игру (показать финальный экран или титры), укажите в кнопке перехода **специальный зарезервированный ID `999`**. Движок автоматически поймет, что сюжет завершён, и плавно остановит игровой сеанс:
```json
"buttonsMap": {
  "Выйти к свету (Завершить игру)": 999
}
```

### 🚀 Инструкция по запуску игры
1. Сформируйте свои уровни в папке `levels` по инструкции выше.
2. Запустите файл **`NovellaEngine.exe`** двойным кликом мыши.
3. Движок сам отсканирует файлы, свяжет их между собой и начнет игру со стартового 1-го уровня.
  * ❗ При наличии ошибки в структуре json вы увидите информацию об этом на стартовом экране и номер файла с ошибкой

## 🛠️ ТЕХНИЧЕСКАЯ ДОКУМЕНТАЦИЯ (DEVELOPER GUIDE)

Этот раздел предназначен для описания архитектурных решений проекта и проведения Code Review.

### 🏗️ Архитектурные особенности и рефакторинг
Кодовая база проекта соответствует современным инженерным практикам:
* **Инверсия управления (IoC):** Класс `NovellaController` полностью избавлен от скрытых состояний. Все ключевые зависимости (`GameDataLoader`, `SoundPlayer` и др.) внедряются в него извне через конструктор.
* **Умный перехват и изоляция ошибок JSON:** В движке реализована система отказоустойчивости  при работе с пользовательским контентом. Если создатель новеллы допустит синтаксическую ошибку в JSON-файле (например, забудет кавычку или запятую), приложение перехватит ошибку и выведет  информацию и номер файла на стартовый экран. 
* Логи о работе приложения пишутся в текстовый файл **`logs.txt`** для удобной отладки.
* **Ресурсная безопасность (Java NIO):** Сканирование файловой директории `levels` реализовано с помощью реактивных Java-стримов (`Files.list`). Обязательное использование конструкции `try-with-resources` гарантирует мгновенное освобождение дескрипторов операционной системы при чтении папок, полностью исключая утечки ресурсов.
* **Снижение когнитивной нагрузки:** Тяжелые вложенные блоки обработки исключений `try-catch` внутри циклов были  инкапсулированы в отдельные приватные методы с единственной зоной ответственности, что сделало основной поток выполнения линейным и легко читаемым.

### 💻 Технологический стек
* **Язык разработки:** Java 21 LTS (с использованием современных оптимизаций компилятора)
* **Архитектурный паттерн:** MVC (Model-View-Controller)
* **Формат данных:** JSON (динамический маппинг переходов)
* **Логирование:** Встроенная файловая система логирования с выводом отчётов в `logs.txt`
